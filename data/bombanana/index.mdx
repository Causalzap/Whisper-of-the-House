<GuideQuickAnswer title="Quick Answer">
**BOMBANANA** is a three-player co-op bomb-defusal game built around incomplete communication between Blind, Deaf, and Mute monkeys. The fastest way to stop losing runs is to standardize every callout: **module → position → required state → manual answer → repeat → confirm → input**.

For the current playable version, there are **7 levels**. Wires need **wire count + LED + colors**, Direction needs **LED + Braille**, Numpad needs **equation result + LED + odd/even**, and Switches need the **full light order + all four numbers** before you touch Enter.

<h2 id="how-to-play">
  How to Play BOMBANANA
</h2>

BOMBANANA only becomes manageable after the team stops treating it like normal co-op voice chat. Each player loses a different communication tool, so the group has to pass information through a chain instead of everyone shouting at the bomb at once.

### Blind

Blind handles the bomb and interacts with the physical modules. The important habit is to describe **position and state**, not just whatever detail seems most obvious. If I am on wires, I say the wire count and LED before the colors. If I am on Direction, I give the LED and Braille value before asking for a direction.

### Deaf

Deaf is the visual relay. The role becomes much easier when I face the Mute player for the answer, translate the gesture into one instruction, then turn back to the bomb handler. Trying to follow two conversations at once is where clean information turns into noise.

### Mute

Mute holds the manual and has the correct logic but cannot simply explain it. The best questions are therefore short and answerable with **yes / no / number / direction / repeat**. A question like “Do we flip the second switch?” is much easier to answer than “What are we supposed to do with this panel?”

<h2 id="wires-manual">
  BOMBANANA Wires Manual
</h2>

Wires are the best module for learning the communication format because the information package is small:

**wire count → LED color → wire colors left to right → final cut as color + position**.

Do not skip the count. Three-wire and four-wire cases are not interchangeable. Do not stop at the color either; I repeat the final instruction as something like **“blue, second wire from the left”** before cutting.

<h2 id="direction-manual">
  BOMBANANA Direction / D-pad and Braille Manual
</h2>

Direction looks simple until the team realizes two different information channels are involved. The visible player calls the **LED color**, while the tactile / Braille value supplies the number. The manual holder combines those two pieces and returns a direction.

My callout format is:

**Direction, [position]. [LED color]. Braille [number]. Waiting for direction.**

The second problem is perspective. Players facing one another naturally mirror left and right, so we agree before the run that **left and right always mean the bomb handler's perspective**. Once that rule is fixed, the module becomes much faster.

<h2 id="calculation-manual">
  BOMBANANA Calculation / Numpad Manual
</h2>

The Numpad is where the game stops being “just do the math.” It is a **two-stage module**.

1. Read the equation carefully and calculate the result.
2. Enter that raw result on the keypad.
3. Read the new LED color and classify the result as odd or even.
4. Use the LED + odd/even mapping to get the final single digit.

That third step is where many runs fail. The equation can be correct and the module can still be unfinished.

<h2 id="switch-manual">
  BOMBANANA Switch Module Manual
</h2>

The Switch panel is the first module where partial information is genuinely dangerous. I do not solve it one color at a time as the numbers arrive. I collect the whole state first:

**full light order → all four numbers → solve each physical switch → confirm all four → Enter**.

### Why the light order matters

The light order tells the manual holder **which rule family is active**. That is why the same color can require a different switch state in another run. A Red / Yellow / Blue / Green panel cannot safely reuse the logic from Green / Blue / Yellow / Red.

### Why all four numbers matter

Some rules are direct, but others compare the current value with another color's number. In one successful sequence, a later switch depended on whether its number was greater than or less than the red value. If I only hear the current number, I may have to stop and request the entire sequence again.

This is why our repeat language matters so much:

- **repeat once** = say the last item again
- **repeat twice** = re-read the full light order and all four numbers

<h2 id="levels-1-7">
  BOMBANANA Levels 1–7 Guide
</h2>

The level section is most useful as a progression guide. I use it to know which manual mechanic the team should be comfortable with before moving on, not as a fixed list of every module that must appear in the same position every run.

### Level 1 — Learn the wire callout

Level 1 is where I establish the core rhythm: **module → state → answer → repeat → act**. The puzzle itself is simple enough that almost every failure comes from communication rather than logic.

If the Blind player hears only “cut blue,” that is still incomplete. I want “blue, second wire from the left” before the cut.

### Level 2 — Add Direction and Braille

Level 2 adds the Direction / D-pad problem. The important lesson is that the LED and Braille number belong together. Early attempts often fail because one player gives the color while another player assumes the number is decorative or already understood.

This is also where I lock the team's left/right perspective. Doing it later is too expensive.

### Level 3 — The Numpad is two-stage

Level 3 introduces the math / Numpad flow. The common mistake is celebrating after the equation result is accepted. The LED that appears next is not decoration; it starts the second lookup.

Once the team starts saying **“result 63, Yellow, odd”** instead of just “63,” the module becomes much more reliable.

### Level 4 — Stop talking over modules

By Level 4, the challenge is less about discovering a new rule and more about maintaining clean separation between familiar modules. I say **“done”** after each solved panel and then restart the next callout from its name.

This prevents the manual holder from finishing a Numpad lookup while the bomb handler has already started describing Direction.

### Level 5 — Switches become the real wall

Level 5 is **not the final level**. It is important because the Switch panel becomes the major new manual-heavy problem.

A successful Level 5 sequence included wires, Direction, and a four-switch panel. The first attempts became chaotic because the team read colors and numbers piecemeal. The later successful approach was much cleaner: collect the full light order, collect the full number string, then resolve switches one by one before Enter.

### Level 6 — More state, less recovery time

Level 6 can combine Direction, more than one math input, and Switch logic in the same run. The main danger is carrying stale information from one panel into the next.

I reset the callout format every time we move modules. If we leave Numpad and move to Switches, the first words should be **“Switches, [position]”**, not another number with no context.

### Level 7 — Current final level

Level 7 is the current maximum. In the runs I checked it could include **multiple Switch panels plus Direction and math**, which turns the level into a communication stress test rather than a brand-new tutorial.

The best run solved the Switch state first, moved through Direction with short LED + number calls, then finished the math with only seconds left. That is exactly why I do not want to learn a new communication language on Level 7; every signal should already be automatic.

<h2 id="best-module-order">
  Best Module Order in BOMBANANA
</h2>

There is no single order I force onto every bomb, but I use one practical rule: **take the fastest familiar win first, then spend the saved time on the manual-heavy panel**.

My default priority is:

1. **Wires** if the state is immediately readable.
2. **Direction** once the team has the LED + Braille mapping and perspective locked down.
3. **Numpad** if the arithmetic is straightforward and the manual holder is ready for the second-stage key.
4. **Switches** when the whole team can stop and give the manual holder the complete state cleanly.

The exception is a level with multiple Switch panels or an awkward bomb layout. In that case I may start with the slow module while everyone is calm instead of saving it for the final ten seconds.

<h2 id="common-mistakes">
  Common BOMBANANA Mistakes
</h2>

The failures that cost us the most time were usually not obscure puzzle rules. They were communication errors that repeated across several modules.

### Giving information without naming the module

“Red, seven” is useless if the manual holder does not know whether I mean Direction, Numpad, or Switches. Start with the module and position.

### Forgetting wire count

Three-wire and four-wire cases use different branches. Wire count belongs before the colors.

### Mirroring left and right

When players face each other, one person's left is the other's right. Decide whose perspective is authoritative before the timer starts.

### Treating the math result as the final Numpad answer

The raw equation result is only stage one. After it is entered, read the new LED and odd/even state before pressing the final key.

### Reading Switch information one item at a time

Switch rules can refer back to another color's number. Read the complete light order and complete four-number string first.

### Pressing Enter with one uncertain switch

A panel with three confirmed switches and one guess is still a failed panel. If one state is uncertain, use the rewind or repeat-all signal before Enter.

### Reusing the old state after a mistake

A wrong input can change the state you are looking at. Re-read the module instead of repeating the previous answer automatically.

<h2 id="faq">
  BOMBANANA FAQ
</h2>

### How many levels are in BOMBANANA?

The current playable version has **7 levels**, and Level 7 is the current maximum.

### Is Level 5 the final BOMBANANA level?

No. Level 5 is where the Switch panel becomes a major new mechanic, but the current progression continues through Levels 6 and 7.

### What should I call out first for every module?

Start with the **module name and position**. Then give only the state that module needs: wire count and LED for Wires, LED + Braille for Direction, equation result + LED + odd/even for Numpad, or full light order + four numbers for Switches.

### Why does the Numpad need another number after I solve the equation?

Because the calculation module is two-stage. The equation result is entered first, then the LED color and odd/even classification select the final single-digit key.

### Why do Switch answers change between runs?

Because the panel does not use one universal color-to-position rule. The **light order selects the rule family**, and the four numbers determine which conditions are true in that run.

### What should I do if a Switch answer turns out to be wrong?

Do not immediately press Enter again. Re-read the full color order and all four numbers, identify which physical switch needs to change, correct it, and only then confirm the full panel.

<h2 id="find-sounding-symbol" className="scroll-mt-24">
  The Symbol Puzzle Starts With the Sounding Shape
</h2>

Symbol first appears as a fixed Campaign module at **Level 8**.

The panel looks like a visual-description puzzle: four strange shapes, a control that can move between them, and colored buttons waiting for an answer.

That appearance sends a lot of first attempts in the wrong direction.

The useful first question is not:

**“What are all four symbols?”**

It is:

**“Which one is making the sound?”**

The handler rotates the selector through the symbols.

The player who can hear listens.

Once the sound identifies the active shape, I freeze the selector there and stop describing the other three.

That cuts the information problem from four unfamiliar shapes to one.


<h2 id="why-first-attempts-fail" className="scroll-mt-24">
  Describing Everything on the Panel Creates More Work
</h2>

A messy Symbol call can sound like:

**filled star**

**empty star**

**triangle with a line**

**square with a circle**

followed by three colors and several guesses about which row of the manual matters.

Every fact may be accurate.

The team can still have no usable answer.

That happened repeatedly before the missing step became clear: the four displayed shapes are not four simultaneous manual lookups.

The sound chooses the one that matters now.

Once that is understood, the call becomes much smaller:

**“Symbol. Sounding shape is hourglass.”**

Then the manual holder only has to locate **hourglass** for the current stage.

This is also why I avoid reading all three button colors aloud unless somebody actually needs their positions. They are outputs, not the identity of the puzzle.


<h2 id="four-stages" className="scroll-mt-24">
  One Correct Button Does Not Finish the Module
</h2>

Symbol is sequential.

A successful first answer advances the puzzle rather than ending the whole interaction.

The useful mental model is:

**hear → identify → look up → press → advance**

then:

**hear → identify → look up → press → advance**

again.

There are **four stages** in the sequence.

That stage number matters because the same symbol does not guarantee the same answer later.

This was one of the more expensive misunderstandings in early attempts. A color that looked correct for a symbol in the first row was reused as though the symbol had one permanent answer.

It does not work that way.

The symbol identifies the manual entry.

The **current stage** selects which part of that entry matters.

So after every successful press, the previous answer is finished.


<h2 id="clean-run" className="scroll-mt-24">
  A Clean Symbol Exchange Uses One Shape at a Time
</h2>

Once the team understands the sound check, the module becomes much easier to follow.

A later sequence moved through calls like:

**circle with a vertical line**

then:

**triangle with a line**

then another active shape on the following stage.

The important part is not memorizing those exact shapes.

It is the order of operations.

For each stage:

1. Rotate until the sound source is identified.
2. Leave the selector on that symbol.
3. Give that symbol one stable name.
4. Find the same symbol in the manual.
5. Read the answer for the **current stage**.
6. Press the matching button.
7. Confirm the stage advanced before starting another lookup.

If step 7 never happens, I assume the previous input was wrong rather than immediately continuing with stage two.


<h2 id="name-the-shapes" className="scroll-mt-24">
  The Best Symbol Name Is the One the Team Recognizes Twice
</h2>

Symbol does not require elegant vocabulary.

It requires repeatable vocabulary.

Several shapes are easy to describe differently every time.

One player may say:

**hourglass**

another:

**two triangles touching**

and somebody else:

**the eight-looking one**

Those can all refer to the same object.

Under a timer, three names make it feel like three objects.

So after a description works once, I keep it for the session.

Useful names from real calls included things such as:

- **filled star**
- **empty star**
- **hourglass**
- **square with a circle**
- **circle with a vertical line**
- **triangle with a line at the top**
- **triangle with a line at the bottom**

These are not official names that the team has to memorize.

They are examples of names that distinguish one visible shape from another quickly.

The dangerous description is the one that changes halfway through the solve.


<h2 id="similar-symbols" className="scroll-mt-24">
  “Square With a Circle” and “Circle With a Square” Are Not the Same Call
</h2>

One Symbol failure is especially useful because the problem was not the manual rule.

The team believed it was looking at the correct shape.

Then somebody asked whether the call meant:

**a circle with a square inside**

or:

**a square with a circle inside**.

That distinction was enough to explain why a lookup that seemed correct produced the wrong input.

When two shapes are structurally similar, I name the **outer shape first**:

**square with circle inside**

or:

**circle with square inside**

That small convention is much safer than shortening both to:

**“the square-circle one.”**

If the manual answer looks impossible, this is one of the first descriptions I re-check.


<h2 id="when-not-to-press" className="scroll-mt-24">
  Three Uncertainties Mean My Hand Stays Off the Buttons
</h2>

A wrong Symbol answer often starts several seconds before the actual button press.

I stop the input if any of these are unresolved:

**The sounding symbol is not confirmed.**

Seeing a familiar shape is not enough. The sound is what makes it active.

**Two people are describing different shapes.**

A fast manual lookup against the wrong symbol only produces a fast mistake.

**Nobody agrees on the current stage.**

Stage one and stage three can send the same symbol to different answers. The old color cannot be carried forward just because the shape repeats.

In those cases, guessing has very little upside.

Rotate again, listen again, confirm the symbol, then resume from the stage the module is actually showing.


<h2 id="after-wrong-input" className="scroll-mt-24">
  After a Wrong Button, I Rebuild the Current State
</h2>

The instinct after a failed press is to argue about the last color:

**“I thought you said Green.”**

That usually leaves the more important questions unanswered.

Before another input, I want four things settled:

**Which stage are we on now?**

**Which symbol is currently selected?**

**Is that actually the symbol producing sound?**

**Which manual row is being read?**

Only then does the color answer matter again.

If somebody has started rotating while the manual reader is still defending the previous lookup, the old answer is already stale.

That is my reset point.


<h2 id="level-8-practice" className="scroll-mt-24">
  Level 8 Is Where I Fix Symbol Before Piano Joins the Conversation
</h2>

Level 8 is the first fixed Symbol level.

Level 9 introduces Piano.

Level 10 can put **Symbol + Piano** together under Alarm pressure.

That makes Level 8 valuable for one specific reason: it gives the team a chance to make the Symbol vocabulary boring before another communication-heavy module arrives.

I stay around this part of the Campaign when a Symbol still causes:

- a long description of all four shapes;
- repeated arguments over which shape is selected;
- color guesses before anybody listens;
- confusion over the stage number;
- different names for the same shape every time it appears.

Once one stage can move from sound to button without re-explaining the whole panel, I am ready to push deeper.

<h2 id="symbol-or-communication" className="scroll-mt-24">
  A Correct Lookup Can Still Reveal the Wrong Problem
</h2>

There are two very different kinds of Symbol failure.

If the wrong shape was selected, the stage was lost, or the manual entry was misread, the problem belongs here.

If everyone already knows the active symbol and correct button but that answer never reaches the handler clearly, rereading the Symbol procedure will not help much.

That is a relay problem.

The <Link href="/bombanana/roles">Blind, Deaf & Mute Roles Guide</Link> is where I fix unclear gestures, dropped information, and the handoff between players.

For Symbol itself, the checkpoint is simpler:

**sound confirmed → one shape name → current stage → one button → confirm advancement**

When those five pieces stay intact, the panel stops feeling like a wall of random glyphs.

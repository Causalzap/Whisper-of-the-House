<section
  id="quick-answer"
  className="scroll-mt-24"
>
  <GuideQuickAnswer title="30 Levels, Five Real Progression Breakpoints">

  BOMBANANA has **30 Campaign levels**, but I do not treat them as thirty separate walkthroughs.

  The progression changes most around these five stretches:

  **Levels 1–7:** Easy modules, basic callouts, first Chaos pressure  
  **Levels 8–15:** Symbol, Piano, Soundboard, and Random Medium modules  
  **Levels 16–20:** Switch and Maze make complete state calls more important  
  **Levels 21–24:** Morse and Monkey-Says add sequence memory  
  **Levels 25–30:** Random Hard modules and heavier Chaos become the test

  If the same module is still consuming most of the timer at the end of one stretch, I fix that weakness before pushing into the next one.

  </GuideQuickAnswer>
</section>


<h2
  id="all-levels"
  className="scroll-mt-24"
>
  All 30 BOMBANANA Campaign levels
</h2>

<GuideTable
  caption="BOMBANANA full-release Campaign progression. Random slots pull from their listed difficulty pool, so those module combinations can vary."
  columns={levelColumns}
  rows={levelRows}
/>

Levels 1 and 2 allow **one mistake**.

From Level 3 onward, the allowance rises to **three**.

The timer starts at **2:30**, spends much of the middle Campaign around **4:00**, and reaches **5:00** on several later levels.

The longer timer does not necessarily mean an easier bomb.

Level 20, for example, can combine:

**Maze + Switch + Random Easy**

with:

**Pressure + Alarm**

Level 29 gives the same five-minute timer but already asks for:

**3 × Random Hard**

while Slider, two Pressure hazards, and Alarm compete for attention.

More time usually arrives because the team is carrying more state, not because the game is becoming forgiving.


<h2
  id="levels-1-7"
  className="scroll-mt-24"
>
  Levels 1–7 build the communication system
</h2>

Level 1 starts with **Cable**.

Level 2 introduces **Color Slider**.

Level 3 combines both.

Those first three levels are less about difficulty and more about establishing how the team describes physical positions and how it ends one module call before starting another.

If Cable is already the weak point, use the <Link href="/bombanana/wire">Cable / Wire Guide</Link> rather than repeatedly guessing through Level 3.

Level 4 introduces <Link href="/bombanana/direction">Direction</Link> and the first **Slider Chaos**.

This is where I settle the team's left/right perspective before later bombs add more competing state.

This is where a fixed left/right perspective becomes important.

Level 5 introduces **Calculator**.

Calculator adds the first obvious state transition:

**equation first → LED stage second**

The full Calculator procedure and answer table are in the <Link href="/bombanana/calculator">Calculator Guide & Solver</Link>.

Level 6 combines:

**Calculator + Cable + Color Slider**

with **Pressure**.

That is the first early bomb where a slow solve also means another system is being neglected.

Level 7 changes the structure again:

**4 × Random Easy**

with Slider Chaos.

The game is no longer testing whether the team remembers a fixed level composition.

It is testing whether the easy-module procedures still work when the combination changes.

<Image
  src="/images/bombanana/bombanana-chaos-modules.webp"
  alt="BOMBANANA manual explaining that Chaos Modules must be managed while the bomb is being defused"
  width={1600}
  height={900}
  className="my-8 rounded-xl"
/>

Before leaving this block, I want:

- Cable to need one clean packet rather than repeated rereads;
- Direction to use one agreed physical perspective;
- Calculator's missing-light first stage to stop causing hesitation;
- one Chaos problem to be managed without pulling all three players away from the bomb.

If the rules are understood but the relay itself keeps failing, the <Link href="/bombanana/roles">Roles Guide</Link> is the better place to fix it.


<h2
  id="levels-8-15"
  className="scroll-mt-24"
>
  Levels 8–15 make descriptions and sequences more expensive
</h2>

Level 8 introduces **Symbol**.

The new difficulty is partly vocabulary: the team needs names for shapes that stay consistent from one attempt to the next.

Level 9 introduces **Piano**.

Piano asks the group to carry several pieces of information through the same solve instead of one short lookup.

  src="/images/bombanana/bombanana-piano-yellow-light.webp"

  width={1600}
  height={900}
  className="my-8 rounded-xl"
/>

Level 10 combines **Symbol + Piano** under Alarm.

Level 11 introduces **Soundboard** beside Symbol.

<Image
  src="/images/bombanana/bombanana-campaign-level-11-select.webp"
  alt="BOMBANANA Campaign level selector showing Level 11"
  width={1600}

  className="my-8 rounded-xl"
/>

From Level 12 onward, the Campaign stops introducing one perfectly isolated module at a time.

Level 12 uses:

**Random Easy + Soundboard + Random Medium**

with:

**Pressure + Slider**

Levels 13 and 14 lean harder into Random Medium modules.

Level 15 reaches:

**2 × Random Easy + 2 × Random Medium**

with:

**Slider + Alarm**

At this point I stop asking for a single “Level 15 solution.”

The useful question is:

**Which Medium module is still slow?**

If Symbol descriptions take too long, I fix the naming system.

If Piano information keeps disappearing halfway through the sequence, I fix the packet.

If Soundboard starts with the team describing everything before identifying the relevant sound target, I fix the order of the call.

For broader module procedures, use the <Link href="/bombanana/module-solver">Module Solver & Manual</Link>.


<h2
  id="levels-16-20"
  className="scroll-mt-24"
>
  Levels 16–20 punish incomplete state calls
</h2>

Level 16 introduces **Switch**.

Level 17 keeps Switch while adding a Random Medium slot.

Level 18 introduces **Maze**.

Level 19 mixes Maze with Easy and Medium random modules.

Level 20 combines:

**Random Easy + Maze + Switch**

with:

**Pressure + Alarm**

and gives the team **5:00**.

Switch and Maze create different kinds of state problems.

With Switch, partial information can make the team act on an incomplete state.

With Maze, a route can be perfectly reasonable but still fail if the starting position or destination was misunderstood.

So the checkpoint for this stretch is simple:

**Switch:** can the team preserve the complete current state?

**Maze:** can the team establish the starting state before movement begins?

Level 20 is the real test.

If it only succeeds when the Random Easy slot is especially friendly, I treat that as evidence that one of the fixed modules or the Chaos management is still too slow.


<h2
  id="levels-21-24"
  className="scroll-mt-24"
>
  Levels 21–24 make sequence memory part of the run
</h2>

Level 21 introduces **Morse**.

Level 22 combines Morse with a Random Medium module plus Alarm and Pressure.

Level 23 introduces **Monkey-Says**.

Level 24 combines:

**Random Easy + Monkey-Says + Maze**

with:

**Pressure + Slider**

The major change here is that earlier information can still matter later.

With an early Cable, the old state can usually disappear from memory once the cut is complete.

With sequence-heavy modules, dropping an earlier item can damage a later stage.

I therefore stop letting all three players remember “most of the sequence.”

One person keeps the accumulated chain.

Another confirms the current stage.

Blind waits until both agree before committing the next input.

The goal is not to make every call slower.

It is to prevent the team from reaching the end of a sequence and asking:

**“What was stage two again?”**


<h2
  id="levels-25-30"
  className="scroll-mt-24"
>
  Levels 25–30 are endgame pools, not six fixed solutions
</h2>

The final six levels lean heavily on **Random Hard** slots.

Level 25:

**Random Medium + 2 × Random Hard**

Level 26:

**Random Easy + Random Medium + Random Hard**

with all three main Chaos types.

Level 27:

**Random Medium + 2 × Random Hard**

Level 28:

**3 × Random Hard**

with Slider, Pressure, and Alarm.

Level 29:

**3 × Random Hard**

with Slider, **2 × Pressure**, and Alarm.

Level 30:

**4 × Random Hard**

with **2 × Alarm**.

The structure is fixed, but the specific Hard modules inside those random slots can vary.

That is why there is no single useful button-by-button “Level 30 solution.”

What survives between attempts is the team's procedure.

If one Hard module still causes everyone to stop and rediscover the rule each time it appears, that is the weakness I practice.

If every module is understood but all three players abandon the defusal chain whenever Chaos becomes dangerous, I fix Chaos responsibility instead.

The late Campaign tests whether several learned systems can stay alive at once.

<h2
  id="replay-or-push"
  className="scroll-mt-24"
>
  Replay when the same failure keeps surviving the retry
</h2>

An explosion by itself is not enough reason to move backward.

A single run can fail because of:

- one accidental input;
- a brief Chaos miss;
- a bad random combination;
- one misheard callout.

I replay or step backward when the **same cause** survives multiple attempts.

If Cable repeatedly ends with Blind receiving a color but no physical position, I fix the <Link href="/bombanana/wire">Cable handoff</Link>.

If Calculator repeatedly stalls because the team waits for an LED before entering the arithmetic result, I fix the <Link href="/bombanana/calculator">Calculator flow</Link>.

If the rule answer is correct but information disappears between players, I fix the <Link href="/bombanana/roles">role and communication setup</Link>.

If the team cannot explain what the module is asking for at all, I return to the <Link href="/bombanana/module-solver">Module Solver & Manual</Link>.

The useful retry is the one where something has changed.

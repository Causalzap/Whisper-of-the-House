<GuideQuickAnswer title="Quick Answer">
My reliable early Duck setup is:

**Automated Duck Workbench → short straight lane → staged Fans → side walls → catcher → Pit**

The base automatic source makes **1 Duck every 5 seconds**, or **12 Ducks per minute**.

The later **1 Duck every 2 seconds** upgrade raises that to **30 Ducks per minute**, which is **2.5× the source rate**.

I only buy that speed upgrade after the current lane can clear the five-second output without building a growing pile.

For Ducks, I add a roof only where they are actually bouncing out, wait for Sticky Tools before I commit to a permanent build, and keep the main route simpler than any combo path.

I consider the Duck line finished when it can run in the background without constant sweeping or rescue.
</GuideQuickAnswer>

<h2 id="first-layout">
  My first Duck layout is a straight lane with a wide catch
</h2>

I get the best early results from a layout that is easy to read.

My baseline is:

**workbench**

→ **one clear direction**

→ **staged airflow**

→ **side containment where needed**

→ **wide catcher**

→ **Pit**

If I need several Fans just to correct several bad turns, I simplify the lane before I spend more.

<h2 id="fan-stages">
  I use Fans in stages instead of trying to launch Ducks across the room
</h2>

I do not need one Fan to solve the whole route.

I give each stage one job.

**The first Fan** gets Ducks away from the source.

**A middle Fan** keeps the lane moving if there is a real dead zone.

**The final Fan** helps the last approach without throwing Ducks past the catch.

I only add a new Fan when I can point to a clear section where Ducks repeatedly lose momentum.

I do not add one because the factory simply looks busy.

The moment I am unsure whether the problem is force, geometry, or the catcher, I stop tuning here and use the <Link href="/project-pitt/automation-layouts">Layout Helper</Link>.

<h2 id="roof">
  I add a roof only after Ducks prove they can escape upward
</h2>

A roof is not part of my first purchase list.

I wait until I see Ducks bouncing over the side walls.

I cover the failure zone first.

If Ducks keep escaping farther down the line, I extend the roof.

If they stop escaping, I leave the rest open.

That gives me more room to reach the lane with a broom, move a Fan, or clear a pile without dismantling a sealed tunnel.

A roof can also become part of the problem if I make a chute too cramped.

Ducks need enough vertical room to roll and recover after a bad landing.

So I treat containment as something I add **locally**, not as a rule that every Duck route must become a full tunnel.

<h2 id="sticky-tools">
  Sticky Tools are when I consider rebuilding the Duck lane properly
</h2>

Before Sticky Tools, I treat most Panels and Fans as temporary.

Once I can freeze tool positions against surfaces, a cleaner permanent lane becomes much more attractive.

I usually revisit the Duck setup when Sticky Tools let me:

**straighten the main corridor**

**fix side walls in place**

**lock Fans where their airflow already works**

**remove temporary support pieces**

I do not rebuild just because Sticky Tools unlocked.

If the old line is already feeding reliably, I leave it alone.

I rebuild when moving hardware is the reason the Duck route is difficult to maintain.

That is the difference between buying a useful upgrade and buying an excuse to redo a working factory.

<h2 id="upgrade-to-two-seconds">
  I upgrade from five seconds to two seconds only after the lane clears itself
</h2>

The most important Duck production decision is the jump from:

**1 Duck every 5 seconds**

to:

**1 Duck every 2 seconds**

The base rate is:

**60 / 5 = 12 Ducks per minute**

The faster rate is:

**60 / 2 = 30 Ducks per minute**

That is a **2.5× increase**.

I only buy it when:

- the source area clears before the next Duck arrives;
- the first Fan does not develop a growing pile;
- the catcher is not already overflowing;
- I can leave the line alone without repeatedly sweeping the same spot.

If the five-second lane is only barely surviving, the two-second upgrade is not more production.

It is a faster jam.

<h2 id="duck-jams">
  A repeated Duck jam makes me inspect the lane before I increase production
</h2>

One useful Duck-specific lesson came from a chute that looked like it needed more airflow.

It did not.

A Fan had ended up inside the travel path and created a physical obstruction.

That changed the way I react to a Duck pile.

I do not immediately upgrade the workbench or buy a stronger Fan.

I first make sure the route itself is still physically clear.

I keep the full jam / obstruction / airflow decision tree in the <Link href="/project-pitt/automation-layouts">Automation Layout Helper</Link>, because the same diagnosis applies beyond Ducks.

The Duck-specific decision is simpler:

**if the lane is not clearing at the current source rate, I do not increase the source rate yet.**

<h2 id="bumpers">
  I add Bumpers for combos only after the direct route is stable
</h2>

Bumpers can make the Duck line more interesting and can help create longer combo chains.

I do not use them as the foundation of the first reliable route.

Every bounce adds another variable.

A Duck going directly from the workbench toward the Pit is easy to read.

A Duck that hits multiple Bumpers, a wall, a Fan stream, and a roof can fail in several different places.

So my order is:

**stable direct route first**

→ **bonus Bumper path second**

If the combo path starts creating a growing pile or throwing Ducks out of the main lane, I remove the bonus piece before I start adding extra Fans to compensate for it.

A lower-maintenance Duck stream is more valuable to me than a prettier combo setup that needs constant rescue.

<h2 id="magnet">
  I use the Magnet for Duck recovery, not as the main conveyor
</h2>

The Magnet is useful when Ducks have already escaped or when I want to gather a loose group for manual cleanup.

I do not build the main Duck transport around it.

For my normal flow:

**Fans move the Ducks**

**walls contain them**

**the catcher receives them**

The Magnet is the recovery tool.

That keeps the main route predictable and stops a large Duck cluster from forming around the Magnet itself.

<h2 id="when-to-stop">
  I stop spending on Ducks when Cash Registers need the money more
</h2>

I consider the early Duck line finished when all of these are true:

**the workbench can stay on**

**the entrance does not build a growing pile**

**Ducks are not repeatedly escaping from the same spot**

**the catcher can handle the current source rate**

**I can leave the line alone while I work elsewhere**

Once Cash Registers unlock, they become the better use of my attention and money.

I let the Duck line keep generating background income and move to the <Link href="/project-pitt/cash-register-automation">Cash Register Automation guide</Link>.

I only come back to Ducks when a later unlock directly changes an old problem.

Sticky Tools can be a reason.

A stronger Fan can be a reason.

A higher production rate creating a new bottleneck can be a reason.

“Make the old factory look nicer” is not a reason.

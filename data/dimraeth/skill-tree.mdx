<GuideQuickAnswer title="Quick Answer">
Earn XP, return to a training point, and spend that XP on an attribute to level up and receive Skill Points. Before buying nodes, choose the skill or mechanic you want to reach, then follow the connected path toward it. Use the tree's **Search** box for terms such as Bleed, and use Respec when an early route no longer fits the character.

<h2 id="how-skill-points-work">
  How do you get Skill Points in Dimraeth?
</h2>

The first thing that confused me was seeing XP accumulate while the Skill Tree still showed **Available Points: 0**. Killing more enemies was not the missing step.

Dimraeth separates earning XP from actually turning that XP into character levels. Once I reached a place where training was available, I spent XP on an attribute, confirmed the training, and the character advanced a level. Going from Level 1 to Level 2 gave me **two Skill Points**.

So when the tree stays at zero points even though you have been fighting for a while, the sequence is:

1. earn XP;
2. reach a training point;
3. spend XP to raise an attribute;
4. confirm the training;
5. open the Skill Tree and spend the points you gained.

One of the early places where I could do this was **Farland's Roadside Camp**. Training is also available through progression NPCs later, so there is no reason to keep grinding the same enemies because you think XP itself will eventually create Skill Points.

The tree is a large connected network rather than a short list of upgrades. The screenshot above has **0 Available Points and 2 Spent Points**, but most of the board is still untouched.

That scale makes random one-point purchases expensive. A node next to the center may look useful, but every point spent away from the route you actually need delays the next skill by another training cycle.

I treat the larger active skills as destinations. Once I know which one matters next, I trace the connected nodes back toward my current position and see what the route will cost.

<h2 id="race-class-tree">
  Your race and class both affect the tree you receive
</h2>

The board is not universal across every character.

When comparing different combinations, I found that changing the race or class changes parts of the Skill Tree as well as the character's starting combat style. That is why a route copied from another player's “Brawler” or “Shadow” can look different when your race does not match theirs.

The exact differences between Human, Minotaur, Elf, Brawler, Magician, and Shadow start at character creation, so check the <Link href="/dimraeth/classes">Dimraeth classes guide</Link> if you are still deciding which combination to make.

Once the character already exists, I work with the tree in front of me rather than trying to reproduce a route built for a different race/class pairing.

Some smaller nodes give straightforward bonuses such as health, stamina, or a damage type. Other nodes alter an ability you already have. The larger skill nodes can add something that actually changes what buttons the character has available in combat.

That distinction matters early because two points spent on minor bonuses may feel immediately useful without solving the character's real limitation.

On one Elf Shadow tree, for example, I could see routes toward new tools such as **Shadow Convergence** and **Plague Shards**. Getting there required buying the connected path first. The visible skill is therefore only part of its actual Skill Point cost.

Before committing points, I ask what those connecting nodes are buying me on the way to the destination. A health or damage node on the correct route is much easier to justify than the same bonus sitting several branches away.

In the example above, I typed **bleed** and the tree highlighted matching nodes while unrelated branches faded into the background. The character had **22 Spent Points** at that stage, so manually checking every visible branch would have been much slower.

Search is especially useful once the character already has a direction. If I know I care about Bleed, I search Bleed first, inspect where those highlighted nodes sit, and then work backward to the nearest reachable route.

The search result does **not** mean every highlighted node should be purchased. It only answers “where are the nodes that mention this mechanic?”

The next step is still to check:

- how many connecting nodes are required;
- whether those nodes support the same character;
- whether another branch reaches a more important active skill first.

That keeps Search from turning into a checklist where every matching result gets bought automatically.

<h2 id="route-cost">
  Count the path, not just the skill you want
</h2>

A skill that appears only a few inches away on the zoomed-out board can still require several purchases because the paths bend through stat nodes, modifiers, and junctions.

I therefore start from the desired node and follow the line back toward the closest node I already own.

Suppose I have two new Skill Points. If the ability I actually want is four connected purchases away, spending those two points on unrelated nearby bonuses means I am still four purchases away next level. Spending them on the required path puts me halfway there.

That sounds obvious once the board is understood, but the tree is large enough that early characters can easily accumulate a collection of useful-looking nodes without reaching another ability.

The mistake becomes more expensive later because the tree keeps opening outward while the number of points remains limited.

<h2 id="attributes">
  Skill Points and attributes advance together, but they solve different problems
</h2>

Training connects two progression systems.

XP is spent to raise attributes, the training advances your character level, and that level gives you Skill Points. The Skill Points then move through the tree.

At the same time, abilities and spellbooks can have attribute requirements. That means a character can be moving toward the correct Skill Tree branch while its attribute training is moving in a completely different direction.

Before spending a large amount of saved XP, I check the next ability or spell I actually intend to use. If it needs an attribute I have neglected, finding that out before confirming several other upgrades saves a later correction.

The exact attribute priorities depend on the build. The <Link href="/dimraeth/builds">Dimraeth builds guide</Link> handles the full Shadow and Bleed Brawler progression; here the useful rule is simply to keep the next attribute breakpoint and the next Skill Tree destination pointed toward the same character plan.

<h2 id="build-route">
  Do not copy a finished Skill Tree without knowing when its skills became useful
</h2>

A late-game-looking tree can hide the order that made it work.

For example, a Bleed character may eventually contain many Bleed-related nodes. That does not mean the correct Level 2 decision was to buy whichever Bleed node was closest. Early progression may need another active ability first, while stronger status interactions become valuable only after the character has reliable ways to apply that status.

The same problem appears with damage bonuses. A percentage increase can be excellent once the character already has enough abilities to clear comfortably. Earlier in the run, another usable attack may solve more fights than a slightly larger number on an existing one.

This is why I separate **how the Skill Tree works** from the finished route I use for a particular character. If you are following the Minotaur Bleed or Shadow status setup, use the route in the <Link href="/dimraeth/builds">builds guide</Link> rather than turning every example here into a universal priority.

After reaching **Earlwood Village**, I found the respec option through the training side of character progression. Opening it brings up the Skill Tree with a **Respec Cost** display and a **Respec All** control.

In the screen shown here, the displayed **Respec Cost is 1**.

That makes an early wrong branch recoverable, but I still wait until I know what the replacement route is supposed to accomplish. Resetting because one new node looks interesting can simply trade one unfinished path for another.

I respec when there is a concrete reason: the current route is blocking an ability I now want, my attributes and equipment can support a different setup, or the earlier investment no longer contributes to how the character actually fights.

<h2 id="when-to-respec">
  A bad node is not always worth resetting immediately
</h2>

One or two imperfect early purchases are rarely enough to make the character unusable.

The decision becomes more important when the points are stranded on a branch I no longer intend to continue. At that stage, the hidden cost is not only the points already spent there; it is every future level I would need to keep delaying the route that now matters more.

Before resetting, I check the new route on the tree first. I locate the destination, count its connecting nodes, and confirm that I can actually reach something meaningful with the points being returned.

That prevents a frustrating cycle where I reset, discover the desired skill is still too far away, and end up with a weaker version of the character I had before.

<h2 id="early-priority">
  What should you spend your first Skill Points on?
</h2>

With only a few points available, the strongest purchase is usually the one that moves the character toward a **real combat tool**, not the node with the most attractive isolated percentage.

On my early characters, I got better results by choosing the next ability first and accepting useful health, stamina, or damage nodes that happened to sit along that route.

That gives each level a clear purpose. Instead of opening an enormous tree and asking which of hundreds of nodes is best, I only need to answer a much smaller question:

**What is the next skill or mechanic this character needs, and which connected path gets me there without wasting the points I have now?**

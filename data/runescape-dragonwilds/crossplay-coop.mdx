<GuideQuickAnswer title="Quick Answer">
**RuneScape: Dragonwilds supports crossplay in 1.0.** PC, PlayStation 5, Xbox Series X|S, and Nintendo Switch 2 players can play together when the host enables Crossplay for that multiplayer session. A normal player-hosted world supports **4 players total**, while a Dedicated Server supports **up to 6**. Use the World Browser or an Invite Code to join friends. <h2 id="does-dragonwilds-have-crossplay">
  Does RuneScape: Dragonwilds have crossplay?
</h2>

Yes. Dragonwilds 1.0 supports crossplay across its PC and console platforms, including **Steam, Epic Games Store, Jagex Launcher, PlayStation 5, Xbox Series X|S, and Nintendo Switch 2**.

Crossplay is controlled when a multiplayer world is hosted. You can choose whether the world allows cross-platform players each time you load it for multiplayer, so the setting is not a permanent commitment when the world is first created.

That distinction is useful if you started on PC alone and a console friend joins later. You do not need a new world just because the original session was solo.

<h2 id="how-many-players">
  How many players can play Dragonwilds co-op?
</h2>

A normal player-hosted world supports **4 players total — the host plus up to three friends**.

A **Dedicated Server supports up to 6 players**.

The other important difference is availability. A normal friends world exists as an online session while its host is running it. A Dedicated Server can stay available independently as long as the server itself remains online.

For a two- to four-player group that normally plays together, I would start with a normal hosted world. Dedicated Server setup becomes worth the extra work when six-player capacity or always-available access actually solves a problem for the group.

<h2 id="enable-crossplay">
  How do I enable crossplay?
</h2>

When loading or setting up a multiplayer world, turn on **Enable Crossplay** before starting the session.

The world can also have a password.

These settings solve two different problems:

- **Crossplay** controls whether players on other platforms can join.
- **Password** controls who can enter after finding or receiving access to the world.

A private cross-platform game therefore needs Crossplay enabled and can also use a password to keep the session limited to your group.

</h2>

Once the host has loaded the multiplayer world, friends can find it through the **World Browser**.

Dragonwilds 1.0 also added **Invite Codes**. The host can find the code from the in-game pause menu, while the joining player enters that code from the World Browser.

For a private group, the quickest sequence is:

1. Load the world as multiplayer.
2. Enable Crossplay if the group uses different platforms.
3. Set a password if you want the world private.
4. Start hosting.
5. Open the pause menu and copy the Invite Code.
6. Send the Invite Code and password to the other players.

The Invite Code is especially useful when several public worlds have similar names because friends do not have to find yours manually in the browser.

<h2 id="solo-world-to-coop">
  Can I start solo and let friends join later?
</h2>

Yes.

You can start the world alone, build your base and make normal progress, then later load that same world for multiplayer when your friends are ready.

If they are playing on another platform, enable Crossplay when you host it.

That makes starting solo much less risky. A friend buying the game several hours or several days later does not force you to abandon the world you already built.

The practical issue is progression rather than world compatibility. Someone joining a well-established world may arrive much less prepared than the existing players. I keep spare food, a basic weapon, armor, and common materials at the base instead of immediately dragging a new player into whichever high-level region the host is currently clearing.

If both players are starting from scratch, the <Link href="/runescape-dragonwilds/beginner-guide">beginner guide</Link> covers the survival, combat, Rune, storage, and early-base systems that matter before the group starts pushing farther across Ashenfall.

<h2 id="hosted-vs-dedicated">
  Should I use Play with Friends or a Dedicated Server?
</h2>

The deciding factor is usually **when people want access to the world**.

Use **Play with Friends** when the group has four or fewer players and normally plays together. It requires almost no server administration, and it is the setup I would use before investing time in a Dedicated Server.

Use a **Dedicated Server** when the group needs:

- up to **6 simultaneous players**;
- a world available while the original player is offline;
- independent access for people playing on different schedules;
- server administration and persistent hosting.

<h2 id="cross-save">
  Does Dragonwilds have cross-save or cross-progression?
</h2>

No. **Crossplay and cross-save are separate features in Dragonwilds.**

Crossplay lets players on different platforms enter the same multiplayer world.

It does not let you transfer your existing save from one platform to another.

For example:

**Steam → play with a PS5 friend:** yes.

**Move your Steam save to PS5 and continue it there:** no.

Steam has its own Steam Cloud support, but that does not convert the save into a transferable PlayStation, Xbox, or Switch 2 save.

This is worth deciding before putting dozens of hours into a platform because buying a second copy elsewhere does not move that existing progression with you.

<h2 id="epic-online-services">
  Do Steam players need an Epic Games account for crossplay?
</h2>

You do **not** need to create an Epic Games Store account or install the Epic Games Launcher just to play Dragonwilds online from Steam.

Dragonwilds uses **Epic Online Services** for its online infrastructure. On Steam, the game can make that connection using your public Steam ID without requiring you to maintain a separate Epic Games Store login.

If you declined the online connection when first setting up the game and multiplayer is unavailable, open:

**Settings → Legal → Update EOS Settings**

and enable the online connection there.

You can still play solo offline without using the online multiplayer services.

<h2 id="dedicated-server-requirements">
  What are the Dragonwilds Dedicated Server requirements?
</h2>

Self-hosted Dragonwilds servers support **64-bit Windows and Linux**.

The RAM requirement is:

**2 GB base RAM + 1 GB for each player**

That works out to:

| Players | Recommended server RAM |
| ---: | ---: |
| 2 | 4 GB |
| 4 | 6 GB |
| 6 | 8 GB |

The server currently supports up to **6 players**.

Dedicated Servers use **UDP port 7777** by default. If you run additional servers, the next server uses 7778, then 7779, and so on.

Those UDP ports need to be reachable from outside your network. If friends can see the server in the browser but cannot actually connect, port forwarding is one of the first things to check.

You can install the free **RuneScape: Dragonwilds Dedicated Server** product through Steam or SteamCMD.

<h2 id="dedicated-server-config">
  Where is DedicatedServer.ini and what does it need?
</h2>

Stop the server before changing its configuration. Changes made while the server is running can be lost.

On Linux, the configuration file is:

```text
Files/RSDragonwilds/Saved/Config/Linux/DedicatedServer.ini
```

For Windows Server, create the corresponding file at:

```text
Files/RSDragonwilds/Saved/Config/WindowsServer/DedicatedServer.ini
```

Four values are required for the server to function correctly:

- **Owner ID**
- **Server Name**
- **Default World Name**
- **Admin Password**

The **Owner ID** is your Dragonwilds Player ID. You can copy it from the bottom of the in-game Settings menu.

The names are easy to mix up.

**Server Name** identifies the server itself.

**Default World Name** controls the name of the default world created when the server does not already have a save to load.

A **World Password** is optional. Leave it empty if you want the world joinable without one.

<h2 id="find-dedicated-server">
  How do I find my Dedicated Server?
</h2>

Open the Worlds screen and go to the **Public** tab.

Search for the exact **World Name**. The search is case-sensitive, so capitalization matters.

If it does not appear, I check these before changing anything else:

1. Server and client are on the same game version.
2. The World Name being searched matches the world the server is actually running.
3. Owner ID, Server Name, Default World Name, and Admin Password are present.
4. The server log does not show a startup error.

Updates and hotfixes are a common reason a server suddenly disappears.

The server version is shown near the top of its logs, and the client version can be compared against it. If they differ, update or restart the server before touching the world save.

<h2 id="visible-but-cannot-join">
  Why can I see my server but not join it?
</h2>

When the server appears in the browser but outside players cannot connect, check the network path before blaming the save.

The default server uses **UDP 7777**. Your firewall, router, and any other router between the server machine and the ISP need to allow that traffic to reach the server.

Some ISPs do not allow normal inbound port forwarding at all, which can make a home-hosted server harder to expose publicly.

There is also a Dedicated Server-specific connection issue worth recognizing: **Steam Invite is not the reliable way to enter a Dedicated Server**. If an invite does nothing, search for the world through the Public World Browser instead.

<h2 id="move-world-to-dedicated-server">
  How do I move an existing world to a Dedicated Server?
</h2>

You can move a world that started locally instead of rebuilding from zero.

Before copying the save, **stop the Dedicated Server and back up its current Savegames folder**.

Your local Windows world saves are stored at:

```text
C:\Users\your_username\AppData\Local\RSDragonwilds\Saved\SaveGames
```

The Dedicated Server reads worlds from:

```text
RSDragonwilds/Saved/Savegames
```

To move the world:

1. Stop the Dedicated Server.
2. Back up everything currently inside `RSDragonwilds/Saved/Savegames`.
3. Empty the server's `Savegames` folder.
4. Find the `.sav` file for the local world you want to move.
5. Copy that `.sav` file into the server's `RSDragonwilds/Saved/Savegames` folder.
6. Start the Dedicated Server.

The server loads the latest `.sav` available in that folder.

If there is no `.sav` file there, the server creates a new Standard world instead. If migration appears to have “reset” the world, check the server Savegames folder before assuming the old save itself is damaged.

<h2 id="dedicated-server-logs">
  Where are the Dedicated Server logs?
</h2>

If the server starts incorrectly, disappears after an update, or refuses to load the world you expect, check:

```text
RSDragonwilds/Saved/Logs/RSDragonwilds.log
```

The log is particularly useful for confirming:

- the server version;
- startup failures;
- which world the server is loading;
- configuration problems.

For a clearer console while self-hosting through Steam, add these launch options to the Dedicated Server:

```text
-log -NewConsole
```

That gives you live server feedback instead of requiring every failure to be diagnosed from the World Browser.

<h2 id="crossplay-not-working">
  What should I check if crossplay is not working?
</h2>

For a normal player-hosted world, I check the session itself first:

1. Make sure the world was loaded for multiplayer rather than solo.
2. Confirm **Enable Crossplay** is on when players are using different platforms.
3. Re-enter the world password if one is set.
4. Try the Invite Code instead of only searching manually in the World Browser.
5. Make sure every player has installed the latest update or hotfix.
6. On Steam, check the EOS connection under **Settings → Legal** if online multiplayer was previously declined.

For a Dedicated Server, add these checks:

- server and client versions match;
- the exact case-sensitive World Name is being searched;
- all mandatory `DedicatedServer.ini` values are present;
- UDP 7777 is reachable;
- the server has been restarted after an update;
- the server log does not show a configuration or save-loading error.

I would not delete or replace the world save as the first troubleshooting step.

A server that disappeared immediately after a patch, a world visible but unreachable, and a player-hosted Crossplay world that cannot be found are three different problems. Check version, hosting settings, and network access before touching the actual save.

<h2 id="offline-play">
  Can I play Dragonwilds offline?
</h2>

Yes. Dragonwilds can be played solo offline.

Crossplay, public multiplayer worlds, Invite Codes, and Dedicated Servers require the online systems, but the main single-player progression does not.

That means you can start offline, learn the game at your own pace, and open the same world for normal multiplayer later rather than creating a separate co-op save from the beginning.

<GuideQuickAnswer title="Quick Answer">
**RuneScape: Dragonwilds supports crossplay in 1.0.** PC, PlayStation 5, Xbox Series X|S, and Nintendo Switch 2 players can join the same multiplayer world when the host enables **Crossplay**. A normal player-hosted world supports **4 players total**, while a **Dedicated Server supports up to 6**. Friends can join through the World Browser or an Invite Code. Crossplay does **not** include cross-save, so progression does not move from one platform to another.
</GuideQuickAnswer>

<h2 id="does-dragonwilds-have-crossplay">
  Does RuneScape: Dragonwilds have crossplay?
</h2>

Yes. Dragonwilds 1.0 supports cross-platform multiplayer between **Steam, Epic Games Store, Jagex Launcher, PlayStation 5, Xbox Series X|S, and Nintendo Switch 2**.

Crossplay is chosen when a world is loaded for multiplayer. If a world began as a solo save on PC, that does not lock it to solo or to PC. The same world can later be opened for multiplayer, with Crossplay enabled when friends are joining from another platform.

The host controls that setting for the session, so there is no need to create a separate crossplay world just because the group changes later.

<h2 id="how-many-players">
  How many players can play Dragonwilds co-op?
</h2>

A normal **Play with Friends** world supports **4 players total: one host and up to three other players**.

A **Dedicated Server supports up to 6 players**.

The difference is not only player count. A normal friends world depends on the host running that world. If the host goes offline, the multiplayer session is no longer available to the rest of the group. A Dedicated Server can stay online independently, which is much more useful when six people are playing or when everyone logs in at different times.

For a group of two to four people who normally play together, I would start with a normal hosted world. The Dedicated Server setup is useful when persistent access actually solves a problem rather than simply adding more administration.

<h2 id="enable-crossplay">
  How do I enable crossplay?
</h2>

* **World Password** controls who can join after finding the world or receiving access to it.

For a private cross-platform group, enable Crossplay and set a password if you do not want unrelated players joining.

Once the host has loaded the world as multiplayer, the other players can look for it in the **World Browser**. Dragonwilds 1.0 also supports **Invite Codes**, which are much easier than manually searching when several worlds have similar names.

For a private group, the sequence is straightforward:

1. Load the world for multiplayer.
2. Turn on Crossplay if anyone is on a different platform.
3. Set a world password if the session should stay private.
4. Start hosting.
5. Open the pause menu and find the Invite Code.
6. Send the Invite Code and password to the other players.

The joining player enters the code through the World Browser.

<h2 id="solo-world-to-coop">
  Can I start solo and let friends join later?
</h2>

Yes. You can begin alone, build a base, progress normally, and later load the same world for multiplayer.

If the friend is on another platform, enable Crossplay before hosting that session. You do not need to abandon the world or start a fresh co-op save.

The only real problem is character readiness. A player joining a well-established world may arrive with far less equipment than everyone else. I keep basic armor, a usable weapon, food, and common materials at the base instead of immediately taking a new player into whichever late region the host is currently clearing.

If the whole group is starting fresh, the <Link href="/runescape-dragonwilds/beginner-guide">beginner guide</Link> covers the early survival, Runes, storage, combat, and base systems that matter before pushing into harder regions.

<h2 id="hosted-vs-dedicated">
  Should I use Play with Friends or a Dedicated Server?
</h2>

The easiest way to choose is to ask whether the world needs to exist while the original host is offline.

Use **Play with Friends** when the group has four or fewer players and normally plays at the same time. It requires almost no server management and is enough for most small groups.

Use a **Dedicated Server** when the group needs:

* up to **6 players** at once;
* the world available when the original host is offline;
* players joining independently on different schedules;
* persistent server hosting and administration.

<h2 id="cross-save">
  Does Dragonwilds have cross-save or cross-progression?
</h2>

No. **Crossplay does not mean cross-save.**

Crossplay lets a Steam player, for example, enter the same world as a PS5 player. It does not let that Steam player move the same character or save to PS5 and continue there.

In practical terms:

**Steam player joins a PS5 friend's world:** yes.

**Move a Steam save to PS5 and continue the same progression there:** no.

Steam Cloud can still handle saves within the Steam environment, but it does not turn them into transferable PlayStation, Xbox, or Switch 2 progression. If you expect to put a large number of hours into one platform, choose that platform knowing the save will stay there.

<h2 id="epic-online-services">
  Do Steam players need an Epic Games account?
</h2>

No. Playing Dragonwilds online from Steam does not require you to create an Epic Games Store account or install the Epic Games Launcher.

The game uses **Epic Online Services** for online functionality. On Steam, that connection can work through your public Steam ID rather than a separate Epic Games Store login.

If multiplayer is unavailable because the online connection was declined during initial setup, open:

**Settings → Legal → Update EOS Settings**

and enable the online connection.

Solo offline play does not require those multiplayer services.

<h2 id="dedicated-server-setup">
  What do I need to run a Dragonwilds Dedicated Server?
</h2>

Self-hosted Dedicated Servers support **64-bit Windows and Linux**, with a maximum of **6 players**.

The RAM requirement is:

**2 GB base RAM + 1 GB per player**

| Players | Recommended server RAM |
| ------: | ---------------------: |
|       2 |                   4 GB |
|       4 |                   6 GB |
|       6 |                   8 GB |

The default network port is **UDP 7777**. Additional servers increment from there: 7778, 7779, and so on. If outside players cannot connect, those ports need to be reachable through the firewall and router.

The free **RuneScape: Dragonwilds Dedicated Server** can be installed through Steam or SteamCMD.

Before editing server settings, stop the server. Configuration changes made while it is running can be overwritten or lost.

On Linux, the configuration file is:

```text
Files/RSDragonwilds/Saved/Config/Linux/DedicatedServer.ini
```

On Windows Server, use:

```text
Files/RSDragonwilds/Saved/Config/WindowsServer/DedicatedServer.ini
```

The important required values are:

* **Owner ID**
* **Server Name**
* **Default World Name**
* **Admin Password**

The **Owner ID** is the Dragonwilds Player ID shown at the bottom of the in-game Settings menu.

Server Name and Default World Name are not interchangeable. Server Name identifies the server itself, while Default World Name is used when the server has no existing world save to load. A **World Password** is optional.

<h2 id="find-dedicated-server">
  How do I find and join a Dedicated Server?
</h2>

Open the Worlds screen, switch to the **Public** tab, and search for the exact **World Name**.

The search is case-sensitive, so capitalization matters.

If the server does not appear, I check four things before changing the save:

1. Server and client are running the same game version.
2. The World Name matches the world the server is actually loading.
3. Owner ID, Server Name, Default World Name, and Admin Password are present.
4. The server log is not reporting a startup failure.

Game updates and hotfixes are a common reason a server that worked yesterday suddenly disappears. Compare the server version in its logs with the client version before changing the configuration or touching the world files.

If the server appears in the browser but players outside the network cannot connect, check the network path. The default server uses **UDP 7777**, so the firewall, router, and any upstream network equipment must allow that traffic to reach the machine hosting Dragonwilds.

Some home internet connections do not provide normal inbound port forwarding. In that situation, the problem can be the ISP or network topology rather than Dragonwilds itself.

For Dedicated Servers, I would also use the **Public World Browser** instead of relying on a Steam Invite. A Steam Invite doing nothing does not necessarily mean the server itself is broken.

<h2 id="move-world-to-dedicated-server">
  Can I move an existing world to a Dedicated Server?
</h2>

Yes. A local world can be transferred instead of starting over.

On Windows, local Dragonwilds saves are stored under:

```text
C:\Users\your_username\AppData\Local\RSDragonwilds\Saved\SaveGames
```

The Dedicated Server reads its world files from:

```text
RSDragonwilds/Saved/Savegames
```

Before doing anything, **stop the server and back up the current Savegames folder**.

Then:

1. Stop the Dedicated Server.
2. Back up everything currently inside `RSDragonwilds/Saved/Savegames`.
3. Empty the server's active `Savegames` folder.
4. Find the `.sav` file belonging to the local world you want to move.
5. Copy that `.sav` into the server's `RSDragonwilds/Saved/Savegames` folder.
6. Start the Dedicated Server again.

The server loads the latest `.sav` it finds in that folder.

If no `.sav` is available, it creates a new Standard world. If a transferred server suddenly appears to have reset, check the actual Savegames folder before assuming the original world was corrupted.

<h2 id="dedicated-server-logs">
  Where are the Dedicated Server logs?
</h2>

When a server refuses to start correctly, disappears after an update, or loads the wrong world, check:

```text
RSDragonwilds/Saved/Logs/RSDragonwilds.log
```

The log can show the server version, startup failures, configuration problems, and which world is actually being loaded.

If you are running the server through Steam and want live output as it starts, add:

```text
-log -NewConsole
```

That makes it much easier to see a failure immediately instead of diagnosing everything from the World Browser.

<h2 id="crossplay-not-working">
  What should I check if crossplay is not working?
</h2>

For a normal player-hosted world, start with the session itself:

1. Make sure the world was loaded for multiplayer rather than solo.
2. Confirm **Enable Crossplay** is turned on when the players use different platforms.
3. Re-enter the world password if one is set.
4. Use the Invite Code instead of relying only on a manual World Browser search.
5. Make sure every player is on the latest game version.
6. On Steam, check **Settings → Legal → Update EOS Settings** if online access was previously declined.

Dedicated Servers add another layer of possible failures. Confirm the server and client versions match, search the exact case-sensitive World Name, check that the required `DedicatedServer.ini` values are present, make sure UDP 7777 is reachable, and restart the server after an update.

I would not replace or delete the save as the first troubleshooting step. A server disappearing immediately after a patch, a visible server that nobody can connect to, and a normal Crossplay world that a console player cannot find usually point to different causes.

Version mismatch, hosting settings, EOS access, world search, and network reachability are much safer things to check before touching the save.

<h2 id="offline-play">
  Can I play Dragonwilds offline?
</h2>

Yes. Dragonwilds can be played solo offline.

Crossplay, multiplayer worlds, Invite Codes, and Dedicated Servers need the online systems, but the single-player world itself does not.

That means you can begin offline, learn the game, build a base, and make progress before ever opening the world to other players. When friends are ready, load that same world for multiplayer and enable Crossplay if the group is using different platforms.
